## Initial scope: vision transport replay only

The first Replay slice replays recorded camera/time inputs to the already-tested
vision adapter. It does not start Nav2, Fortress, a sensor bridge, hardware
bringup, or a real camera. The adapter has no `/cmd_vel` publisher.

| Role | Topic / value | Contract |
| --- | --- | --- |
| Bag player publisher | `/clock` | The selected bag segment is the single clock source. Playback runs without `ros2 bag play --clock` when the recorded `/clock` topic is selected. |
| Bag player publisher | `/camera/image_raw` | Recorded `sensor_msgs/msg/Image`; header stamp is capture time in the `ros_sim` domain. |
| Bag player publisher | `/camera/camera_info` | Recorded `sensor_msgs/msg/CameraInfo`; frame, dimensions and paired stamp must satisfy the adapter's configured pairing slop. |
| Vision adapter subscriber | Camera pair | `use_sim_time=true`, `clock_domain=ros_sim`; one backend per run (`off` or `mock`). |
| Vision adapter outputs | `/vision/result`, `/vision/status` | Generated by the adapter during replay. Do not replay recorded copies of these topics. |

Use ROS domain 43 and the `replay` profile, resolved by
`resolve_ros_domain("replay", "43")`. The process must reject a conflicting
inherited `ROS_DOMAIN_ID`; do not bridge the replay domain to simulation (42) or
hardware (44). Select only `/clock`, `/camera/image_raw`, and
`/camera/camera_info` for this initial adapter-only run. Exclude `/cmd_vel`,
`/plan`, costmaps and other computed outputs.

## Separate Nav2 input replay

The input-only Nav2 replay passed its first bounded Linux Humble run on
14.10.2026. The archived G5-off bag was converted into one input-only segment
with 93,128 messages; `ros2 bag info` confirmed its topic set. The first Nav2
attempt failed because the gate passed the Fortress profile without the shared
configuration (missing `obstacle_layer.plugin`). The gate now composes both
profiles using the existing navigation helper. A targeted
`linorobot2_navigation` build installed the missing `navigation_common.yaml`;
merged Fortress/common parameters passed offline validation. After separate
approval, replay
`log/replay_runtime/nav2/nav2-replay-20261014-103038-XgKYqd/` passed: all six
inputs had received samples, Nav2 lifecycle nodes activated, both costmaps
published, `/cmd_vel` had no subscriber, and cleanup left an empty ROS graph.
See
[`IMPLEMENTATION_STATUS.md`](IMPLEMENTATION_STATUS.md) for failure evidence.
This is separate from the vision-transport replay above and does not change
or extend any passed G4/G5 acceptance result.

`scripts/segment_nav2_bag.py --bag BAG --output NEW_DIR` reads an existing
sqlite3 G4/G5 rosbag2 without modifying it. `NEW_DIR` must not exist and must
not be inside the source bag. The segmenter splits whenever recorded `/clock`
goes backwards, using bag storage timestamps for the cut. An ambiguous rewind
at a shared bag timestamp fails closed. Each segment has its own manifest with
source and output hashes, bag-time and simulation-time bounds, and per-topic
message counts. Each includes only `/clock`, `/tf`, `/tf_static`, `/scan`,
`/map`, and `/odom`; `/tf_static` history and the most recent earlier `/map`
are carried forward so later segments can be played independently. The
segmenter does not create a navigation goal or transform sensor data.

From the Linux Humble workspace root, run:

```bash
python3 scripts/segment_nav2_bag.py \
  --bag log/g4_runtime/SELECTED_RUN/rosbag \
  --output log/replay_runtime/nav2/SELECTED_RUN_SEGMENTS
SEGMENT="$(realpath log/replay_runtime/nav2/SELECTED_RUN_SEGMENTS/segment-000)"
ROS_DOMAIN_ID=43 bash scripts/test_nav2_replay_gate.sh --segment="$SEGMENT"
```

The Nav2 gate requires an otherwise empty ROS graph in Domain 43 and a valid
segment manifest. It requires the installed navigation launch helper, common
profile and Fortress profile, composes them into the run directory, and records
their hashes. It starts `nav2_bringup/navigation_launch.py` using the composed
parameters, not the full bringup/localization launch, then
replays only the six input topics above. It checks lifecycle activation, input
subscriptions, exactly one `/clock` publisher, and live global/local costmap
messages. It sends no navigation goal and never replays `/cmd_vel`; any
`/cmd_vel` subscriber causes failure. The gate checks for ROS graph cleanup
after stopping the owned Nav2 launch. Domain separation is an operational
isolation, not a security boundary. Do not bridge Domain 43 to simulation or
hardware, and do not run this alongside the Domain-43 vision replay.

This slice tests whether Nav2 can consume captured map/TF/odometry/LiDAR inputs
and produce costmaps. It is not navigation-goal replay, G4/G5 re-execution,
simulator fidelity, sensor-derived mapping, hardware, or safety evidence.
The segmenter and replay gate have ROS-free regression coverage. G5-off
conversion and one-segment Nav2 runtime acceptance passed in Humble. G5-Mock
and both epochs of G4 Run 42 subsequently passed the same gate; the G4 source
contains an actual clock rewind. Goal replay remains outside this contract and
unproven.

The updated Nav2 gate starts concurrent one-shot probes for the six replay
inputs before starting the bag player. Publisher observations run concurrently;
the two costmap probes start immediately after the player. It waits for
lifecycle activation only after playback begins, so recorded `/tf` can provide
the transforms needed by Nav2 costmaps. It checks Nav2 input subscriptions only
after playback and the one-shot probes complete, avoiding both premature
unknown-topic results and counting the CLI probes as Nav2 consumers. A
successful run writes `replay-report.json` in its evidence directory with the
segment-manifest hash, per-topic sample files, `/clock` publisher count,
`/cmd_vel` observation, and graph-cleanup result. The report records one-or-more
sample evidence, not full message totals; when `/cmd_vel` is undiscovered its
count is `null`, not an inferred zero. Topic endpoint snapshots are retained
separately.

## Clock and bag-segment rules

- Choose exactly one `/clock` publisher. For the recommended mode, replay the
  bag's recorded `/clock` data and do **not** enable the player's `--clock` option.
  If a future bag has no recorded `/clock`, that requires a separately specified
  player-generated-clock mode with the recorded `/clock` topic excluded.
- Keep `use_sim_time=true` on replay-time ROS consumers and use only
  `clock_domain=ros_sim` for vision captures. Never compare those stamps with
  `unix_utc`.
- Replay one contiguous capture segment. Existing full G4 bags span Fortress
  stop/restart boundaries and may contain simulation-time rewinds; do not replay
  such a full bag as one continuous timeline. The Nav2 segmenter records segment
  bounds, source bag URI, storage metadata, and SHA-256 in its manifests.
- Inspect actual offered/requested QoS and received message counts for all three
  input topics before asserting transport PASS. Bag metadata/topic declarations
  alone are not proof of delivery.

## Start/stop and acceptance evidence

1. Validate the source bag and selected segment metadata/hash.
2. Fail closed unless `replay/43`, a local Linux Humble overlay and a fresh isolated
   ROS graph are confirmed. Start no simulator, live camera, hardware backend or
   command publisher. Before running the harness, `ros2 node list` in Domain 43
   must show no existing nodes.
3. From the workspace root in the Linux Humble environment, run the acceptance
   harness with the selected segment and one adapter mode:

   ```bash
   SEGMENT="$(realpath log/replay_runtime/segments/vision-transport-v1)"
   bash scripts/test_replay_gate.sh --segment="$SEGMENT" --mode=mock
   ```

   Use `--mode=off` for the disabled-backend run. The harness validates the
   replay profile and segment hashes, then runs this sensor/time-only player
   command:

   ```bash
   ros2 bag play "$SEGMENT" \
     --topics /clock /camera/image_raw /camera/camera_info \
     --disable-keyboard-controls
   ```

   Do not add `--clock`: the recorded `/clock` topic is replayed from the bag.
   The harness verifies its single publisher before starting the consumer, then
   checks delivered camera pairs, outputs and cleanup. Running `ros2 bag play`
   alone does not constitute replay acceptance.
4. The harness starts exactly one vision adapter mode (`off` or fixture `mock`)
   with simulated time enabled. It verifies paired image/CameraInfo samples,
   capture domain/frame, contract-v1 response/status counts and absence of a
   Vision `/cmd_vel` publisher.
5. The harness stops the adapter and player and validates cleanup. Retain the bag
   URI/hash, segment bounds, ROS/domain/profile/overlay versions, QoS observations
   and report.

The initial replay slice validates deterministic sensor/time transport into the
Vision contract only. It is not G5 Nav2 equivalence, perception quality, real
inference, or hardware evidence. The separate Nav2 input replay owns recorded
`/tf`, `/odom`, `/map`, `/scan` and `/clock`; Nav2 owns its costmap outputs.
Localization is not launched. Runtime delivery and cleanup still need to be
proven on the Linux Humble overlay before claiming this replay slice passed.
